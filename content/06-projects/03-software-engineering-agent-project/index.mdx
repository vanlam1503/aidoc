## Learning objectives

Design a bounded multistep workflow, require tests, and obtain approval for external side effects.

## Prerequisites

Complete the prerequisite lesson: [agent-evaluations](/learn/agent-evaluations). If you already know this material, use the practice questions to assess your understanding.

## Theory

A software engineering agent needs more than a single prompt: scope files, read guidance, plan, make small edits, run allowed tests, and report. Bound iterations and spending; dependency changes, migrations, and pushes need separate approval. The user reviews the final diff.

## Architecture

Issue → inspect repository and guidance → plan checkpoint → bounded edits → tests and lint → summarize diff → approve risky actions → user review and merge.

## Practice

Choose a small issue, allowlist commands and files, and checkpoint after planning and before migrations. Evaluate correctness, passing tests, scope discipline, and summary usefulness.

## Common mistakes

Changing too many files; weakening tests to hide a bug; retrying until a green run; pushing or deploying without approval.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What boundaries would you design for a software engineering agent?

**Why essential:** A coding agent needs a bounded workspace and reviewable changes before deployment authority.

**Answer outline:** Give it a scoped workspace, limited credentials, explicit task constraints, and verifiable checks. Separate code changes from privileged merge or deployment actions.

Reference: [Codex sandboxing](https://learn.chatgpt.com/docs/sandboxing).

### 2. What should a deployment approval show the reviewer?

**Answer outline:** Show the exact artifact or commit, intended environment, relevant check results, and pending action. Bind approval to that version; changed code or targets invalidate the earlier decision.

Reference: [LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts).

### 3. How would you resume after the agent process crashes?

**Answer outline:** Reload durable task state and the workspace baseline, inspect completed work, and rerun only necessary checks. Reconcile external operations before replaying them; checkpoints alone do not guarantee exactly-once effects.

Reference: [LangGraph checkpointers](https://docs.langchain.com/oss/javascript/langgraph/checkpointers).
