## Mục tiêu học tập

Thiết kế workflow nhiều bước có giới hạn; bắt buộc test; xin duyệt trước side effect ngoài repo.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [agent-evaluations](/learn/agent-evaluations). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Software engineering agent không phải một prompt duy nhất: nó phải định phạm vi file, đọc hướng dẫn, lập plan, sửa nhỏ, chạy test được phép và báo cáo. Loop cần giới hạn số lần và ngân sách; thay đổi dependency, migration hoặc push cần approval riêng. Người dùng cần review diff cuối cùng.

## Kiến trúc

Issue → inspect repo/guidance → plan checkpoint → bounded edits → tests/lint → summarize diff → approval for risky action → user review/merge.

## Ví dụ TypeScript

```ts
type RunBudget = { maxSteps: number; maxFilesChanged: number; maxRetries: number };
const limits: RunBudget = { maxSteps: 12, maxFilesChanged: 20, maxRetries: 2 };
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Chọn một issue nhỏ, định allowlist lệnh/file, checkpoint sau plan và trước migration. Định eval cho correctness, test pass, scope discipline và usability của summary.

## Lỗi thường gặp

Agent thay quá nhiều file; sửa test để che bug; retry tới khi “xanh”; push/deploy mà không có approval.

### 1. \* Essential — Bạn thiết kế giới hạn nào cho software engineering agent?

**Vì sao cần ưu tiên:** Coding agent cần workspace giới hạn và thay đổi xét duyệt được trước quyền triển khai.

**Gợi ý trả lời:** Cấp workspace có phạm vi, thông tin xác thực hạn chế, ràng buộc nhiệm vụ rõ và kiểm tra xác minh được. Tách sửa mã khỏi merge hoặc triển khai có đặc quyền.

Nguồn kiểm chứng: [Codex sandboxing](https://learn.chatgpt.com/docs/sandboxing).

### 2. Phê duyệt triển khai cần cho người xét duyệt thấy gì?

**Gợi ý trả lời:** Hiển thị đúng artifact hoặc commit, môi trường đích, kết quả kiểm tra liên quan và hành động đang chờ. Gắn phê duyệt với phiên bản ấy; đổi mã hoặc đích làm quyết định cũ không còn đủ.

Nguồn kiểm chứng: [LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts).

### 3. Khôi phục khi tiến trình agent bị crash thế nào?

**Gợi ý trả lời:** Nạp state nhiệm vụ bền vững và baseline workspace, kiểm tra phần đã xong, chỉ chạy lại kiểm tra cần thiết. Đối soát thao tác ngoài trước replay; checkpoint không tự bảo đảm tác động đúng một lần.

Nguồn kiểm chứng: [LangGraph checkpointers](https://docs.langchain.com/oss/javascript/langgraph/checkpointers).
