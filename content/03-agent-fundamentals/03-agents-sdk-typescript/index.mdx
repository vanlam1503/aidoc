## Learning objectives

Identify agent, tool, and handoff objects and decide when the SDK is simpler than custom orchestration.

## Prerequisites

Complete the prerequisite lesson: [tool-calling](/learn/tool-calling). If you already know this material, use the practice questions to assess your understanding.

## Theory

In the Agents SDK, an **agent** is a workflow unit combining a model and instructions with optional runtime behavior such as tools, guardrails, MCP servers, handoffs, and structured outputs. The SDK abstracts the agent loop, tools, handoffs, and tracing. Adopt it when those features solve a real need, while understanding the loop and its limits. Keep instructions, tool contracts, and output validation near the agent definition for review. [OpenAI: Agent definitions](https://developers.openai.com/api/docs/guides/agents/define-agents)

## Architecture

Request → triage agent → conditional handoff to a specialist → policy-controlled tool execution → final response and trace.

## TypeScript example

```ts
const supportAgent = new Agent({
  name: "Support",
  instructions: "Answer from approved support sources.",
  tools: [lookupOrder],
});
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Design a support agent with one read-only tool. Add a handoff to a person when evidence is insufficient or a transaction must be changed.

## Common mistakes

Adding agents when one suffices; losing necessary context during handoff; treating SDK tracing as a security control.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What does the Agents SDK handle around a model?

**Why essential:** Understanding the runtime loop clarifies what the SDK handles and what your server owns.

**Answer outline:** It runs the agent loop and coordinates configured tools and agent behavior. Your application still owns deployment, credentials, tool implementations, storage, and authorization decisions.

Reference: [OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents/sdk).

### 2. When would you choose a handoff instead of an agent as a tool?

**Answer outline:** A handoff lets a specialist take over the conversation. An agent used as a tool returns bounded help while the manager retains ownership of the final answer.

Reference: [Orchestration and handoffs](https://developers.openai.com/api/docs/guides/agents/orchestration).

### 3. Do agent-level input guardrails protect every tool call?

**Answer outline:** No. Their placement follows agent-chain boundaries. Put authorization and effect-specific validation directly around each relevant tool; use approval interruptions for actions requiring human review.

Reference: [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals).
