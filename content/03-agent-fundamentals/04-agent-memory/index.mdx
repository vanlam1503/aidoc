## Learning objectives

Choose state based on its lifecycle and retention requirements.

## Prerequisites

Complete the prerequisite lesson: [context-engineering](/learn/context-engineering). If you already know this material, use the practice questions to assess your understanding.

## Theory

Conversation history preserves chat continuity; working state tracks workflow progress. Long-term memory needs consent, retention limits, and edit/delete controls. Store sourced facts rather than treating every model output as established information.

## Architecture

Message → versioned state schema → checkpoint → select relevant facts → filter by tenant and user → response.

## TypeScript example

```ts
type State = { version: 1; goal: string; awaitingApproval: boolean };
const state: State = { version: 1, goal: "track delivery", awaitingApproval: false };
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Design order-tracking state that survives a reload. Specify retained data, retention periods, and deletion behavior.

## Common mistakes

Storing private model reasoning; mixing tenants; retaining personal data indefinitely; omitting checkpoint versions.

## Interview questions

Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How do thread checkpoints and long-term stores differ?

**Why essential:** Memory scope determines conversation isolation and recovery correctness.

**Answer outline:** Checkpoints retain a thread's execution state. Stores retain application-defined information across threads, such as preferences. Choose scope explicitly and authorize access for the current user.

Reference: [LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence).

### 2. Should an agent keep every conversation turn in the prompt?

**Answer outline:** Not necessarily. Trim or summarize stale history within the context budget while preserving current intent, important decisions, and tool-call relationships. Test recall after compaction.

Reference: [LangChain short-term memory](https://docs.langchain.com/oss/javascript/langchain/short-term-memory).

### 3. What must remain outside a checkpoint?

**Answer outline:** Keep live database connections, runtime clients, and secrets out of serialized state. Persist stable identifiers and recoverable data; recreate transient dependencies when execution resumes.

Reference: [LangGraph Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api).
