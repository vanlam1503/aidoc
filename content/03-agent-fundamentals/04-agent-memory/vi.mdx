## Mục tiêu học tập

Chọn state theo vòng đời và retention.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [context-engineering](/learn/context-engineering). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Conversation history giữ mạch chat; working state giữ tiến trình một workflow; long-term memory cần consent, retention và quyền sửa/xóa. Chỉ ghi fact có nguồn, không biến mọi output model thành dữ kiện.

## Kiến trúc

Message → state schema có version → checkpoint → selector lấy fact liên quan → lọc theo tenant/user → response.

## Ví dụ TypeScript

```ts
type State = { version: 1; goal: string; awaitingApproval: boolean };
const state: State = { version: 1, goal: "track delivery", awaitingApproval: false };
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Thiết kế state theo dõi đơn qua reload; nêu dữ liệu cần giữ, retention và xóa.

## Lỗi thường gặp

Ghi raw reasoning; trộn tenant; lưu PII vô hạn; không version checkpoint.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Checkpoint theo thread khác long-term store thế nào?

**Vì sao cần ưu tiên:** Phạm vi memory quyết định cách ly hội thoại và độ đúng khi khôi phục.

**Gợi ý trả lời:** Checkpoint giữ trạng thái thực thi của một thread. Store giữ thông tin ứng dụng qua nhiều thread, như sở thích. Chọn rõ phạm vi và kiểm tra quyền truy cập theo người dùng.

Nguồn kiểm chứng: [LangGraph persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence).

### 2. Agent có nên giữ mọi lượt hội thoại trong prompt không?

**Gợi ý trả lời:** Không nhất thiết. Cắt hoặc tóm tắt lịch sử cũ theo giới hạn context nhưng giữ ý định hiện tại, quyết định quan trọng và quan hệ tool call. Kiểm tra khả năng nhớ sau rút gọn.

Nguồn kiểm chứng: [LangChain short-term memory](https://docs.langchain.com/oss/javascript/langchain/short-term-memory).

### 3. Những gì phải ở ngoài checkpoint?

**Gợi ý trả lời:** Không serialize kết nối database đang mở, runtime client và bí mật. Lưu định danh ổn định cùng dữ liệu có thể khôi phục; tạo lại phụ thuộc tạm thời khi chạy tiếp.

Nguồn kiểm chứng: [LangGraph Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api).
