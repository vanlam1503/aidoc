## Mục tiêu học tập

Tách server adapter khỏi UI; validate input; xử lý response và lỗi mà không lộ secret.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [structured-outputs](/learn/structured-outputs). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Responses API cung cấp một giao diện tạo model response có thể chứa văn bản, tool call và nhiều loại item. Client SDK nên nằm server-side để bảo vệ API key. Ứng dụng cần chọn model theo yêu cầu, giới hạn input/output, gắn request ID và xử lý timeout, rate limit cùng refusal.

## Kiến trúc

UI → route handler validate payload → service gọi SDK → normalize response → UI render trạng thái; secrets chỉ nằm trong server environment.

## Ví dụ TypeScript

```ts
import OpenAI from "openai";
const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
const response = await client.responses.create({ model: process.env.OPENAI_MODEL!, input: "Explain context windows briefly." });
const answer = response.output_text;
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Thiết kế route nhận câu hỏi có giới hạn 4.000 ký tự. Viết bảng trạng thái cho success, refusal, timeout, quota và API key thiếu.

## Lỗi thường gặp

Tạo SDK ở client component; tin rằng mọi output chỉ có text; log request kèm token hoặc dữ liệu riêng tư.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Vì sao chỉ đọc output[0].content[0].text không an toàn?

**Vì sao cần ưu tiên:** Phải đọc đúng đầu ra trước khi xử lý tool call hoặc streaming.

**Gợi ý trả lời:** Đầu ra Responses có thể gồm message, tool call và loại item khác. Kiểm tra type của từng item; dùng helper text của SDK khi chỉ cần văn bản tổng hợp.

Nguồn kiểm chứng: [OpenAI text generation](https://developers.openai.com/api/docs/guides/text).

### 2. Bên nhận streaming xác định thành công thế nào?

**Gợi ý trả lời:** Xử lý sự kiện vòng đời có type riêng với text delta. Hoàn thành, lỗi và mất kết nối cần trạng thái khác nhau; văn bản xuất hiện một phần chưa chứng minh lượt chạy thành công.

Nguồn kiểm chứng: [Streaming API responses](https://developers.openai.com/api/docs/guides/streaming-responses).

### 3. previous_response_id có làm lịch sử hội thoại miễn phí không?

**Gợi ý trả lời:** Không. Nó nối trạng thái response, còn đầu vào trước trong chuỗi vẫn có thể tính phí. Theo dõi usage và độ dài context; trạng thái được lưu không đồng nghĩa token miễn phí.

Nguồn kiểm chứng: [OpenAI conversation state](https://developers.openai.com/api/docs/guides/conversation-state).
