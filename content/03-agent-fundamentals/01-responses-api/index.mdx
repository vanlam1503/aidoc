## Learning objectives

Separate the server adapter from the UI, validate input, and handle responses and errors without exposing secrets.

## Prerequisites

Complete the prerequisite lesson: [structured-outputs](/learn/structured-outputs). If you already know this material, use the practice questions to assess your understanding.

## Theory

The Responses API creates model responses that may contain text, tool calls, and other item types. Keep the SDK client on the server to protect the API key. Choose a model for the task, bound inputs and outputs, attach request IDs, and handle timeouts, rate limits, and refusals.

## Architecture

UI → route handler validates payload → service calls SDK → normalize response → UI renders status; secrets stay in the server environment.

## TypeScript example

```ts
import OpenAI from "openai";
const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });
const response = await client.responses.create({ model: process.env.OPENAI_MODEL!, input: "Explain context windows briefly." });
const answer = response.output_text;
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Design a route that accepts questions up to 4,000 characters. Define states for success, refusal, timeout, quota exhaustion, and a missing API key.

## Common mistakes

Creating the SDK in a client component; assuming all output is plain text; logging requests with tokens or private data.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — Why is reading only output[0].content[0].text unsafe?

**Why essential:** Correct output parsing is required before handling tool calls or streaming.

**Answer outline:** Responses output can mix messages, tool calls, and other items. Inspect item types, or use the SDK text helper when you only need aggregated text.

Reference: [OpenAI text generation](https://developers.openai.com/api/docs/guides/text).

### 2. How should a streaming consumer detect success?

**Answer outline:** Handle typed lifecycle events separately from text deltas. Completion, failure, and connection loss need distinct outcomes; visible partial text alone does not establish successful completion.

Reference: [Streaming API responses](https://developers.openai.com/api/docs/guides/streaming-responses).

### 3. Does previous_response_id make conversation history free?

**Answer outline:** No. It links response state, while earlier input in the chain can still be billed. Track usage and context growth instead of equating stored state with free tokens.

Reference: [OpenAI conversation state](https://developers.openai.com/api/docs/guides/conversation-state).
