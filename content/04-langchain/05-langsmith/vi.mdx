## Mục tiêu học tập

Đọc trace nhiều bước; xử lý dữ liệu nhạy cảm; kết hợp trace debugging với eval dataset.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [langchain-js](/learn/langchain-js). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Tracing ghi lại span của prompt, model, retriever và tool để tìm nơi latency hoặc lỗi phát sinh. Dataset-driven evaluation giúp so sánh thay đổi có hệ thống. Trace có thể chứa input/output nhạy cảm; cần redact, giới hạn retention và quyền truy cập trước khi bật trong production.

## Kiến trúc

Request ID → spans cho retrieve/model/tool → redaction → trace store → dataset cases → scorer/review → release decision.

## Ví dụ TypeScript

```ts
type SpanSummary = { name: string; durationMs: number; error?: string };
function slow(span: SpanSummary): boolean { return span.durationMs > 1200; }
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Tạo schema trace tối thiểu cho RAG. Đánh dấu field được lưu, redact field riêng tư, và chọn metric để phát hiện retrieval chậm.

## Lỗi thường gặp

Ghi toàn bộ PII vào trace; tối ưu theo một trace; nhầm log quan sát với metric đánh giá chất lượng.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Tracing bổ sung gì ngoài câu trả lời cuối của assistant?

**Vì sao cần ưu tiên:** Trace hữu ích cần ghi được luồng thực thi mà không lộ dữ liệu nhạy cảm.

**Gợi ý trả lời:** Nó cho thấy lời gọi model, context truy xuất, tool, thời gian và lỗi trong lượt chạy. Dùng luồng đó để tìm truy xuất sai hoặc lời gọi không cần thiết.

Nguồn kiểm chứng: [LangSmith Observability](https://docs.langchain.com/langsmith/observability).

### 2. Offline evaluation khác online evaluation thế nào?

**Gợi ý trả lời:** Offline so các phiên bản trên dataset tuyển chọn trước phát hành. Online theo dõi lưu lượng thật và phát hiện lỗi mới; đưa các lỗi đã xét duyệt vào dataset hồi quy.

Nguồn kiểm chứng: [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types).

### 3. Trace assistant nhiều tenant mà không ghi bí mật thế nào?

**Gợi ý trả lời:** Che dữ liệu nhạy cảm trong input, output và metadata trước khi gửi đi. Cân nhắc tắt tracing với request bị hạn chế; quy định quyền truy cập và thời gian lưu trace.

Nguồn kiểm chứng: [Prevent logging sensitive trace data](https://docs.langchain.com/langsmith/mask-inputs-outputs).
