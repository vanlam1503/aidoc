## Learning objectives

Read multistep traces, protect sensitive data, and combine trace debugging with evaluation datasets.

## Prerequisites

Complete the prerequisite lesson: [langchain-js](/learn/langchain-js). If you already know this material, use the practice questions to assess your understanding.

## Theory

Tracing records spans for prompts, models, retrievers, and tools to locate latency and failures. Dataset-driven evaluation compares changes systematically. Traces may contain sensitive inputs and outputs; establish redaction, retention, and access control before enabling production tracing.

## Architecture

Request ID → retrieval, model, and tool spans → redaction → trace store → dataset cases → scoring and review → release decision.

## TypeScript example

```ts
type SpanSummary = { name: string; durationMs: number; error?: string };
function slow(span: SpanSummary): boolean { return span.durationMs > 1200; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Define a minimal trace schema for RAG. Mark retained fields, redact private fields, and choose a metric that detects slow retrieval.

## Common mistakes

Logging personal data in traces; optimizing around one trace; confusing observational logs with quality evaluation metrics.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What does tracing add beyond the final assistant response?

**Why essential:** A useful trace must capture the execution path without exposing sensitive data.

**Answer outline:** It reveals model calls, retrieved context, tools, timing, and failures within a run. Use that execution path to locate a bad retrieval or unnecessary call.

Reference: [LangSmith Observability](https://docs.langchain.com/langsmith/observability).

### 2. How do offline and online evaluations differ?

**Answer outline:** Offline evaluations compare versions on curated datasets before release. Online evaluations monitor real traffic and reveal new failure cases; promote reviewed failures into regression datasets.

Reference: [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types).

### 3. How would you trace a multi-tenant assistant without logging secrets?

**Answer outline:** Redact sensitive inputs, outputs, and metadata before export. Consider disabling tracing for restricted requests, and define access and retention policies for recorded traces.

Reference: [Prevent logging sensitive trace data](https://docs.langchain.com/langsmith/mask-inputs-outputs).
