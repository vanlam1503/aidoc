## Learning objectives

Distinguish embeddings from generation, describe chunking and retrieval, and preserve citation provenance.

## Prerequisites

Complete the prerequisite lesson: [context-engineering](/learn/context-engineering). If you already know this material, use the practice questions to assess your understanding.

## Theory

**Retrieval-Augmented Generation (RAG)** combines retrieval from external knowledge sources with generation: the application retrieves relevant information and places it in context so a model can ground its response in those sources. An **embedding** is a numeric vector representation whose geometry can be useful for tasks such as similarity search. Vector distance is a signal, not proof of truth or relevance for every query. Chunk boundaries, metadata, freshness, and access control affect quality before prompting begins. [OpenAI: Retrieval](https://platform.openai.com/docs/guides/retrieval) · [OpenAI: Embeddings](https://platform.openai.com/docs/guides/embeddings)

## Architecture

Sources → parse and normalize → chunks with document IDs and versions → embeddings and index → query rewriting and filtering → retrieve and rerank → attributed context → answer and citations.

## TypeScript example

```ts
type RetrievedChunk = { id: string; text: string; source: string; updatedAt: string };
function cite(chunk: RetrievedChunk): string { return `[${chunk.id}] ${chunk.source}`; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Take five small documents. Choose chunk boundaries and metadata, write five questions, and check whether the expected passage appears in the top three results.

## Common mistakes

Confusing vector similarity with verification; using oversized chunks or losing headings; omitting access controls or source versions.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What changes when you use RAG instead of relying on model weights?

**Why essential:** Separating retrieval from generation makes failures diagnosable.

**Answer outline:** Relevant external evidence is retrieved at query time and supplied to generation. Updating the index changes available evidence without retraining the generator; citations still need verification.

Reference: [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401).

### 2. What do embeddings contribute, and what do they not prove?

**Answer outline:** They represent relatedness for similarity search. Nearby vectors do not establish factual truth, authorization, or a complete answer; preserve document metadata and evaluate retrieved passages.

Reference: [OpenAI vector embeddings](https://developers.openai.com/api/docs/guides/embeddings).

### 3. The answer is wrong. How do you separate retrieval and generation failures?

**Answer outline:** Check whether the required passage was retrieved and actually included. Then assess whether the answer used that passage correctly. Track evidence recall and answer grounding separately.

Reference: [LangChain retrieval](https://docs.langchain.com/oss/javascript/deepagents/retrieval).
