## Learning objectives

Compare vector, keyword, and hybrid search, and specify dimensions, indexes, and tenant filters.

## Prerequisites

Complete the prerequisite lesson: [rag-embeddings](/learn/rag-embeddings). If you already know this material, use the practice questions to assess your understanding.

## Theory

Vector databases store embeddings and support nearest-neighbor queries. Keyword search helps with identifiers and rare terms, while vectors help with different phrasings; hybrid search combines both signals. Choose using data, latency, filtering, backups, cost, and operational capability rather than a generic ranking.

## Architecture

Ingest documents, chunks, vectors, and metadata → query embedding plus lexical query → access filters → fusion and reranking → context with provenance.

## TypeScript example

```ts
type SearchPlan = { vectorK: number; keywordK: number; tenantId: string };
```

## Practice

Design retrieval for a knowledge base with product SKUs and free-form questions. Explain why hybrid search may outperform vector-only retrieval and how to test tenant isolation.

## Common mistakes

Forgetting access filters before retrieval; retaining embeddings for deleted documents; evaluating with only one question.
