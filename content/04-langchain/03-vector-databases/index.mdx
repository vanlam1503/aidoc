## Learning objectives

Compare vector, keyword, and hybrid search, and specify dimensions, indexes, and tenant filters.

## Prerequisites

Complete the prerequisite lesson: [rag-embeddings](/learn/rag-embeddings). If you already know this material, use the practice questions to assess your understanding.

## Theory

Vector databases store embeddings and support nearest-neighbor queries. Keyword search helps with identifiers and rare terms, while vectors help with different phrasings; hybrid search combines both signals. Choose using data, latency, filtering, backups, cost, and operational capability rather than a generic ranking.

## Architecture

Ingest documents, chunks, vectors, and metadata → query embedding plus lexical query → access filters → fusion and reranking → context with provenance.

## Practice

Design retrieval for a knowledge base with product SKUs and free-form questions. Explain why hybrid search may outperform vector-only retrieval and how to test tenant isolation.

## Common mistakes

Forgetting access filters before retrieval; retaining embeddings for deleted documents; evaluating with only one question.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How do exact search and approximate nearest-neighbor search differ?

**Why essential:** Index tradeoffs must be measured before optimizing retrieval latency.

**Answer outline:** Exact search supplies a recall baseline. Approximate indexes trade recall, memory, and build cost for speed; compare results and latency using your own dataset and filters.

Reference: [pgvector indexing and filtering](https://github.com/pgvector/pgvector).

### 2. When does hybrid search help?

**Answer outline:** Semantic search handles related meaning; lexical search helps preserve exact identifiers and terminology. Combine rankings and evaluate queries containing names, codes, and paraphrases.

Reference: [OpenAI retrieval](https://developers.openai.com/api/docs/guides/retrieval).

### 3. Why can a filtered ANN query return fewer than k results?

**Answer outline:** Filtering may occur after approximate candidate selection. Examine selectivity, scan limits, and index settings; benchmark iterative scans or partitioning while preserving tenant authorization.

Reference: [pgvector indexing and filtering](https://github.com/pgvector/pgvector).
