## Learning objectives

Compare single-agent and multi-agent approaches, define handoff contracts, and bound fan-out and total cost.

## Prerequisites

Complete the prerequisite lesson: [agents-sdk-typescript](/learn/agents-sdk-typescript). If you already know this material, use the practice questions to assess your understanding.

## Theory

Multiple agents can help when tasks have separate expertise or permissions, independent parallel work, or a need for independent verification. They add latency, token use, coordination failures, and security surface. Start with a single-agent baseline and add agents only when evaluations show a specific benefit.

## Architecture

Orchestrator decomposes task → specialists with input/output schemas and least privilege → verifier combines evidence → escalate disagreements to a person.

## TypeScript example

```ts
type Subtask = { owner: "docs" | "code"; question: string; budget: number };
const tasks: Subtask[] = [{ owner: "docs", question: "Find API contract", budget: 2 }];
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

For a bug involving documentation and code, define a single-agent baseline and when an independent reviewer would help. Set fan-out and retry limits.

## Common mistakes

Adding agents because they are fashionable; giving every agent identical privileges; failing to reconcile conflicting answers or total budgets.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — When is a multi-agent architecture justified?

**Why essential:** Extra agents need a measured benefit that justifies coordination overhead.

**Answer outline:** Use specialists when context, tools, or ownership boundaries materially improve results. Start with a single-agent baseline and measure quality, latency, cost, and coordination failures.

Reference: [LangChain multi-agent patterns](https://docs.langchain.com/oss/javascript/langchain/multi-agent).

### 2. How do supervisor-as-tools and handoff patterns differ?

**Answer outline:** A supervisor keeps the final response and calls specialists for bounded outputs. A handoff transfers control to a specialist; decide who owns the next user-facing response.

Reference: [Orchestration and handoffs](https://developers.openai.com/api/docs/guides/agents/orchestration).

### 3. How would you stop specialists from looping or duplicating work?

**Answer outline:** Define typed task contracts, ownership, shared budgets, and termination rules. Trace delegation and merge results with explicit conflict handling; parallelize only independent work.

Reference: [LangChain multi-agent patterns](https://docs.langchain.com/oss/javascript/langchain/multi-agent).
