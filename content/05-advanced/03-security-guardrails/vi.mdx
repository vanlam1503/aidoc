## Mục tiêu học tập

Vẽ threat model; phân biệt input/output checks với access control; xác định fail-closed behavior.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [prompt-injection-fundamentals](/learn/prompt-injection-fundamentals). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Guardrails gồm kiểm soát ở nhiều tầng: authentication, authorization, input/output validation, tool allowlists, data minimization, human review và monitoring. Model moderation/classification chỉ là tín hiệu bổ sung. Threat model phải xét người dùng, nội dung RAG, tool output, tenant boundary và hành động có tác động.

## Kiến trúc

Untrusted input → validation/classification → least-privilege tool surface → policy check per call → output filter → audit + incident response.

## Ví dụ TypeScript

```ts
type PolicyDecision = "allow" | "deny" | "review";
function decide(action: string, amount: number): PolicyDecision {
  if (action === "refund" && amount > 0) return "review";
  if (!["lookup", "draft", "refund"].includes(action)) return "deny";
  return "allow";
}
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Threat-model một agent có thể đọc đơn và tạo hoàn tiền. Vẽ trust boundaries, quyền theo user, approval threshold và kịch bản incident.

## Lỗi thường gặp

Dựa vào system prompt như sandbox; cho tool tin vào user ID từ model; lọc output nhưng bỏ authorization phía server.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Vì sao chỉ dẫn cho model không đủ làm hệ thống kiểm soát truy cập?

**Vì sao cần ưu tiên:** Kiểm tra quyền tại nơi tạo tác động giúp giới hạn hậu quả khi model sai.

**Gợi ý trả lời:** Model có thể hiểu sai hoặc làm theo nội dung độc hại. Thực thi danh tính, quyền sở hữu, thao tác cho phép và quyền tối thiểu tại tool phía server trước khi đọc hoặc sửa dữ liệu.

Nguồn kiểm chứng: [OWASP excessive agency (2025 edition)](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/).

### 2. Guardrail làm gì và nên chạy ở đâu?

**Gợi ý trả lời:** Nó kiểm tra điều kiện xác định, như đầu vào cấm hoặc yêu cầu tool rủi ro. Đặt kiểm tra tác động sát nơi thực thi; guardrail cấp agent không bao phủ mọi hành động trung gian.

Nguồn kiểm chứng: [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals).

### 3. Bảo vệ agent chạy trên pull request từ fork thế nào?

**Gợi ý trả lời:** Xem mã và trường sự kiện là không tin cậy. Dùng thông tin xác thực hạn chế và môi trường cách ly, tránh lộ bí mật cho job không tin cậy; tách kiểm chứng khỏi xuất bản có đặc quyền.

Nguồn kiểm chứng: [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use).
