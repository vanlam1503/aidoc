## Learning objectives

Design human-waiting states and approval payloads, and reauthorize when execution resumes.

## Prerequisites

Complete the prerequisite lesson: [langgraph-state-machines](/learn/langgraph-state-machines). If you already know this material, use the practice questions to assess your understanding.

## Theory

Human-in-the-loop workflows suit permission approvals, financial effects, and uncertain information. Persist state, explain the pause, provide sufficient review context, and recheck authorization on resume. Bind approval to a specific action, data/version, and expiry to prevent time-of-check/time-of-use issues.

## Architecture

Plan → risk policy → wait_for_approval(action hash, actor, expiry) → human decision → reauthorize → execute idempotently → audit.

## TypeScript example

```ts
type Approval = { actionId: string; payloadHash: string; approvedBy?: string; expiresAt: string };
function isCurrent(a: Approval, hash: string, now: Date) { return a.payloadHash === hash && new Date(a.expiresAt) > now; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Design refund approval showing the amount, order, and reason. Changing the payload after approval must invalidate that approval.

## Common mistakes

Using a single global approval boolean; omitting expiry; failing to recheck the approver role or changed data.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What must a human approval step persist?

**Why essential:** Human review must pause execution before the action creates a side effect.

**Answer outline:** Persist the proposed action, relevant arguments, run identity, and resumable state. Bind approval to the reviewed action; a material change should require a new decision.

Reference: [LangGraph interrupts](https://docs.langchain.com/oss/javascript/langgraph/interrupts).

### 2. Which steps belong in deterministic orchestration?

**Answer outline:** Put authorization, budgets, state transitions, and required checks in code. Let models handle bounded judgments, then validate their output before selecting an allowed transition.

Reference: [LangGraph workflows and agents](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents).

### 3. What happens if approval expires or the reviewer is unavailable?

**Answer outline:** Keep the action pending or reject it according to policy. Record the outcome and resume only through the authenticated review flow; lack of a response is not approval.

Reference: [Guardrails and human review](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals).
