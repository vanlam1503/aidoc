## Learning objectives

Design stable fixtures, compare metrics, and gate releases by severity rather than a single aggregate score.

## Prerequisites

Complete the prerequisite lesson: [agent-evaluations](/learn/agent-evaluations). If you already know this material, use the practice questions to assess your understanding.

## Theory

A prompt change may improve one input group while harming another. Version the prompt, model configuration, retrieval corpus snapshot, and evaluator in the regression suite. Raw text differences are often noisy; assess behavioral criteria and retain traces needed for investigation.

## Architecture

Pull request → curated evaluation set → compare baseline and candidate → gate on critical failures and quality changes → review diff → promote version.

## TypeScript example

```ts
type Result = { passed: number; criticalFailures: number };
function mayRelease(r: Result): boolean { return r.criticalFailures === 0 && r.passed >= 95; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Define release gates for a support agent. Identify fatal metrics, allowable degradation, and how to update the baseline when behavior changes intentionally.

## Common mistakes

Comparing only exact text; automatically accepting a new baseline; evaluating outside the production environment without recording versions.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What belongs in a prompt regression suite?

**Why essential:** Regression gates should catch critical failures before a prompt reaches users.

**Answer outline:** Version prompts, test inputs, provider settings, and assertions. Include previously observed failures and expected refusal cases so a small wording change cannot silently regress behavior.

Reference: [Promptfoo configuration](https://www.promptfoo.dev/docs/configuration/guide/).

### 2. Why is one exact-string snapshot often insufficient?

**Answer outline:** Semantically correct answers can vary in wording. Test the required behavior with structured assertions or a calibrated rubric; use exact matching only where exact text is a requirement.

Reference: [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types).

### 3. A candidate improves average quality but fails a critical case. Ship it?

**Answer outline:** Apply predefined release gates by failure severity and task slice. Fail the CI job for blocking regressions and retain results for review; do not hide critical failures in an average.

Reference: [Promptfoo CI/CD integration](https://www.promptfoo.dev/docs/integrations/ci-cd/).
