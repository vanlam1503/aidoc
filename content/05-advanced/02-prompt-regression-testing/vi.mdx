## Mục tiêu học tập

Thiết kế fixture ổn định; so sánh metrics; đặt gate theo severity thay vì một điểm tổng.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [agent-evaluations](/learn/agent-evaluations). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Prompt thay đổi có thể cải thiện một nhóm input nhưng làm hỏng nhóm khác. Regression suite nên version prompt, model configuration, retrieval corpus snapshot và evaluator. Chênh lệch output thô thường nhiễu; theo dõi tiêu chí hành vi và lưu trace cần thiết để điều tra.

## Kiến trúc

PR → chạy curated eval set → so sánh baseline và candidate → gate theo critical failures/quality delta → review diff → promote version.

## Ví dụ TypeScript

```ts
type Result = { passed: number; criticalFailures: number };
function mayRelease(r: Result): boolean { return r.criticalFailures === 0 && r.passed >= 95; }
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Chọn release gate cho agent hỗ trợ. Xác định metric fatal, mức giảm cho phép và quy trình update baseline khi hành vi đổi có chủ đích.

## Lỗi thường gặp

Chỉ so exact text; tự động chấp nhận baseline mới; chạy eval khác môi trường production mà không ghi version.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Bộ kiểm thử hồi quy prompt cần gì?

**Vì sao cần ưu tiên:** Cổng kiểm thử hồi quy cần chặn lỗi nghiêm trọng trước khi prompt tới người dùng.

**Gợi ý trả lời:** Quản lý phiên bản prompt, đầu vào kiểm thử, cấu hình provider và assertion. Có lỗi từng gặp và ca cần từ chối để đổi câu chữ nhỏ không âm thầm làm hỏng hành vi.

Nguồn kiểm chứng: [Promptfoo configuration](https://www.promptfoo.dev/docs/configuration/guide/).

### 2. Vì sao một snapshot so chuỗi chính xác thường chưa đủ?

**Gợi ý trả lời:** Câu trả lời đúng nghĩa có thể khác câu chữ. Kiểm tra hành vi cần thiết bằng assertion có cấu trúc hoặc rubric đã hiệu chỉnh; chỉ so chính xác khi văn bản chính xác là yêu cầu.

Nguồn kiểm chứng: [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types).

### 3. Ứng viên tăng điểm trung bình nhưng sai ca quan trọng. Có phát hành không?

**Gợi ý trả lời:** Áp dụng cổng phát hành theo mức nghiêm trọng và nhóm nhiệm vụ. Để CI thất bại khi có hồi quy cần chặn, giữ kết quả để xét; không che lỗi nghiêm trọng trong điểm trung bình.

Nguồn kiểm chứng: [Promptfoo CI/CD integration](https://www.promptfoo.dev/docs/integrations/ci-cd/).
