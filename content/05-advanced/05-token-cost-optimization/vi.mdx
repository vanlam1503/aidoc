## Mục tiêu học tập

Phân rã chi phí và giữ quality guard.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [rag-embeddings](/learn/rag-embeddings). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Chi phí phụ thuộc model, token, tool và retries. Đo theo cohort trước; giảm context trùng, giới hạn output, cache nội dung ổn định hoặc route tác vụ đơn giản. Mọi tối ưu cần eval để tránh tiết kiệm bằng cách giảm chất lượng.

## Kiến trúc

Usage telemetry → phân rã cost → phát hiện lặp → cache/budget/routing → eval quality/cost → rollout.

## Ví dụ TypeScript

```ts
type Budget = { maxInput: number; maxOutput: number; retries: number };
const budget: Budget = { maxInput: 8000, maxOutput: 700, retries: 1 };
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Chọn một tối ưu sau khi phân tích 100 requests; định metric chất lượng không được giảm.

## Lỗi thường gặp

Cắt context tùy tiện; cache cá nhân sai quyền; quên retry cost.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Giảm chi phí mà không âm thầm giảm chất lượng thế nào?

**Vì sao cần ưu tiên:** Tối ưu chi phí cần ràng buộc chất lượng và usage đo được.

**Gợi ý trả lời:** Lập baseline chất lượng, tìm lời gọi tốn kém rồi thử đầu ra ngắn hơn, model nhỏ hơn và ít request thừa. So chi phí mỗi nhiệm vụ thành công, không chỉ mỗi request.

Nguồn kiểm chứng: [OpenAI latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization).

### 2. Prompt caching có giống lưu câu trả lời hoàn chỉnh không?

**Gợi ý trả lời:** Không. Prompt caching dùng lại tính toán cho tiền tố prompt khớp; model vẫn sinh đầu ra. Đo cache usage thật và giá đọc, ghi hiện hành theo model.

Nguồn kiểm chứng: [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

### 3. Vì sao prompt ngắn hơn có thể tiết kiệm ít hơn kỳ vọng?

**Gợi ý trả lời:** Có thể mất tiền tố dùng lại hoặc tăng retry và tool call. So tổng usage, lần ghi và đọc cache cùng chi phí nhiệm vụ thành công trước khi chấp nhận giảm token.

Nguồn kiểm chứng: [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).
