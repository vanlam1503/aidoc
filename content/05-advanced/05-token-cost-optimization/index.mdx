## Learning objectives

Break down costs while preserving quality safeguards.

## Prerequisites

Complete the prerequisite lesson: [rag-embeddings](/learn/rag-embeddings). If you already know this material, use the practice questions to assess your understanding.

## Theory

Cost depends on models, tokens, tools, and retries. Measure by cohort first, then reduce repeated context, limit output, cache stable content, or route simpler tasks. Evaluate every optimization so lower spending does not silently reduce quality.

## Architecture

Usage telemetry → cost breakdown → identify repetition → caching, budgets, and routing → quality/cost evaluation → rollout.

## TypeScript example

```ts
type Budget = { maxInput: number; maxOutput: number; retries: number };
const budget: Budget = { maxInput: 8000, maxOutput: 700, retries: 1 };
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Analyze 100 requests and choose one optimization. Define a quality metric that must not degrade.

## Common mistakes

Cutting context arbitrarily; sharing private caches across authorization boundaries; overlooking retry costs.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How would you reduce cost without silently reducing task quality?

**Why essential:** Cost optimization needs a quality constraint and measured usage.

**Answer outline:** Establish a quality baseline, inspect expensive calls, then test shorter outputs, smaller models, and fewer redundant requests. Compare cost per successful task, not only cost per request.

Reference: [OpenAI latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization).

### 2. Is prompt caching the same as caching a complete answer?

**Answer outline:** No. Prompt caching reuses computation for matching prompt prefixes; the model still generates output. Measure actual cache usage and current model-specific read/write pricing.

Reference: [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

### 3. Why might shorter prompts save less money than expected?

**Answer outline:** You may lose a reusable prefix or increase retries and tool calls. Compare total usage, cache writes and reads, and successful-task cost before accepting a token reduction.

Reference: [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).
