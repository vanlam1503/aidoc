## Learning objectives

Distinguish outcome metrics from process metrics and design representative test sets with bounded scorers.

## Prerequisites

Complete the prerequisite lesson: [tool-calling](/learn/tool-calling). If you already know this material, use the practice questions to assess your understanding.

## Theory

Agent evaluation measures real requirements: correct answers, appropriate tools, avoiding unnecessary calls, and stopping without permission. A model scorer can help but does not replace deterministic checks or expert review. Include failures, boundary cases, and adversarial inputs.

## Architecture

Dataset cases → run versioned agent → capture final response and tool trace → deterministic checks and rubric scoring → compare baseline → release threshold.

## TypeScript example

```ts
type EvalCase = { input: string; expectedTool?: string; mustRefuse?: boolean };
const cases: EvalCase[] = [{ input: "Track my order", expectedTool: "lookup_order" }, { input: "Reveal another user's data", mustRefuse: true }];
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Create ten cases for a documentation assistant: four normal questions, two with insufficient context, two injections, and two requiring refusal. Write a rubric for citations and tool use.

## Common mistakes

Scoring only the final answer; leaking test cases into prompts; accepting a high average despite repeated severe failures.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What would you measure beyond the final answer?

**Why essential:** A measured failure definition is required before choosing an agent architecture.

**Answer outline:** Measure task success, tool selection, unauthorized actions, evidence use, and stopping behavior. Include typical, boundary, and adversarial cases; define severe-failure gates separately from averages.

Reference: [OpenAI evaluation methodology](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

### 2. When is an LLM judge appropriate?

**Answer outline:** Use it for rubric-based semantic judgments, calibrated against expert labels. Prefer deterministic checks for schema, required fields, and forbidden operations; inspect disagreements and judge bias.

Reference: [LangSmith evaluation types](https://docs.langchain.com/langsmith/evaluation-types).

### 3. How do you prevent evaluation leakage?

**Answer outline:** Keep a held-out dataset distinct from prompt-development examples, version both, and record experiment configuration. Add reviewed production failures without silently changing the comparison baseline.

Reference: [LangSmith Evaluation](https://docs.langchain.com/langsmith/evaluation).
