## Learning objectives

Choose checkpoint boundaries, use idempotency, and distinguish transient from permanent failures.

## Prerequisites

Complete the prerequisite lesson: [langgraph-state-machines](/learn/langgraph-state-machines). If you already know this material, use the practice questions to assess your understanding.

## Theory

A checkpoint records workflow state at a resumable boundary. Avoid storing secrets or excessive data. Retry transient failures with backoff and limits; side effects need idempotency or reconciliation. Version checkpoint schemas so new application versions can read older state through a planned migration path.

## Architecture

Node completes → serialize minimal versioned state → durable checkpoint → restart or resume → deduplicate tool side effects → record attempt and error.

## TypeScript example

```ts
type Checkpoint = { schemaVersion: 2; step: string; attempts: number; idempotencyKey: string };
function retryable(status: number) { return status === 429 || status >= 500; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Simulate a timeout after a payment provider accepts a request but before the response arrives. Design recovery that avoids charging twice.

## Common mistakes

Retrying validation failures; unbounded retry counts; unversioned checkpoints or sensitive checkpoint data.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What is a checkpoint, and what does it enable?

**Why essential:** Persisted state must be distinguished from completed external side effects.

**Answer outline:** It is a persisted snapshot of graph state associated with a thread and execution step. It supports continuation and inspection; it is not a transaction over every external service.

Reference: [LangGraph checkpointers](https://docs.langchain.com/oss/javascript/langgraph/checkpointers).

### 2. Why can replay repeat an external side effect?

**Answer outline:** The side effect may succeed before the node result is checkpointed. Persist or derive a stable idempotency key before execution and reconcile unknown downstream outcomes.

Reference: [LangGraph fault tolerance](https://docs.langchain.com/oss/javascript/langgraph/fault-tolerance).

### 3. Which failures should be retried?

**Answer outline:** Retry transient failures with bounded attempts, backoff, and jitter. Do not repeatedly retry invalid input or denied access; apply deadlines and surface an actionable terminal failure.

Reference: [AWS timeouts, retries, and backoff with jitter](https://builder.aws.com/content/3EumjoZascWd1oZiEgL8ORlv3qE/timeouts-retries-and-backoff-with-jitter).
