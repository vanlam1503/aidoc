## Learning objectives

Choose actionable metrics, attach correlation IDs, and design redaction and retention rules.

## Prerequisites

Complete the prerequisite lesson: [agent-evaluations](/learn/agent-evaluations). If you already know this material, use the practice questions to assess your understanding.

## Theory

Logs explain events, metrics reveal trends, and traces connect request steps. AI systems also need signals for tool-call rate, retrieval hits, refusals, tokens, and quality evaluations. Segment metrics by version and use case; avoid logging raw prompts by default when they contain personal data.

## Architecture

Request ID → structured logs and spans → aggregate latency, errors, and usage → alert thresholds → sampled traces and redacted debugging.

## TypeScript example

```ts
type Usage = { inputTokens: number; outputTokens: number; durationMs: number; failed: boolean };
function estimatedCost(u: Usage, inRate: number, outRate: number) { return u.inputTokens * inRate + u.outputTokens * outRate; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Propose five dashboard charts for a RAG agent and one alert for increasing citation errors. Specify data that must stay out of logs.

## Common mistakes

Collecting metrics without an owner or response; logging personal data; averaging away failures affecting a smaller group.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How do a trace and a span differ?

**Why essential:** Correlated operations are needed to locate the source of a failed agent run.

**Answer outline:** A trace follows related work across a request or workflow; a span describes one operation with timing and context. Propagate identifiers across model, retrieval, and tool boundaries.

Reference: [OpenTelemetry traces and spans](https://opentelemetry.io/docs/concepts/signals/traces/).

### 2. What should an AI service dashboard measure?

**Answer outline:** Track latency distributions, traffic, errors, and saturation, then add task quality and token cost. Segment by model and version so aggregate metrics do not conceal regressions.

Reference: [Google SRE monitoring](https://sre.google/sre-book/monitoring-distributed-systems/).

### 3. A slow answer looks correct. What would you inspect?

**Answer outline:** Follow the run trace to find repeated retrieval, unnecessary tools, retries, or a slow model call. Compare the execution path with a successful baseline rather than inspecting text alone.

Reference: [LangSmith Observability](https://docs.langchain.com/langsmith/observability).
