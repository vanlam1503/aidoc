## Learning objectives

Organize a review workflow, classify findings by evidence and severity, and prevent out-of-scope edits.

## Prerequisites

Complete the prerequisite lesson: [agents-md](/learn/agents-md). If you already know this material, use the practice questions to assess your understanding.

## Theory

Agent code review should find incorrect behavior, vulnerabilities, and regressions. Each finding needs a location, reproduction conditions, and impact. Human reviewers validate findings because models can miss issues or report false positives. Preserve a reproduction test when fixing a bug to prevent recurrence.

## Architecture

Diff, requirements, and test context → agent findings with severity and evidence → maintainer triage → targeted fix → regression test → review again.

## TypeScript example

```ts
type Finding = { file: string; line: number; impact: string; evidence: string; confidence: number };
function actionable(f: Finding): boolean { return f.evidence.length > 0 && f.impact.length > 0; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Review a small diff for correctness and security. Record findings, verify them manually, add a test for a confirmed bug, and repeat the review.

## Common mistakes

Requesting a whole-repository review without defining scope; accepting findings without evidence; allowing an agent to merge or deploy independently.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How would you structure a repository bug-fix workflow?

**Why essential:** A reproducible failure is the starting point for a verifiable fix.

**Answer outline:** Reproduce the failure, inspect guidance and relevant code, implement a focused fix, run appropriate checks, and review the final diff against acceptance criteria.

Reference: [Codex testing and review practices](https://learn.chatgpt.com/docs/learn/best-practices).

### 2. How do you preserve unrelated developer changes?

**Answer outline:** Inspect repository status before editing, keep the patch narrow, and review changed hunks. Use a separate worktree when needed; never assume a dirty tree is disposable.

Reference: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli).

### 3. What belongs in an agent handoff?

**Answer outline:** State the resulting behavior, changed areas, evidence from checks, and remaining limitations. Make pending decisions and recovery steps explicit so the next reviewer can continue.

Reference: [Iterating development workflows with Codex](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
