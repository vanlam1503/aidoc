## Mục tiêu học tập

Giải thích skill discovery; viết description phù hợp; xác định khi nào cần script hay reference.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [agents-md](/learn/agents-md). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Skill đóng gói quy trình tái sử dụng để agent áp dụng khi tác vụ phù hợp. Description cần nói rõ tình huống kích hoạt và giới hạn. Chỉ dẫn chi tiết được nạp khi cần; tài nguyên hoặc script nên tách riêng để không làm mọi tác vụ tốn context. Skill không phải cách cấp quyền bí mật hay lách chính sách.

## Kiến trúc

User request → skill metadata match → load instructions/resources → thực hiện quy trình → kiểm tra đầu ra theo acceptance criteria của skill.

## Ví dụ TypeScript

```ts
type SkillManifest = { name: string; description: string; entrypoint: string };
const skill: SkillManifest = { name: "release-notes", description: "Use when preparing a release summary from merged changes", entrypoint: "SKILL.md" };
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Chọn quy trình lặp lại trong team và viết description trigger/anti-trigger, đầu vào, bước làm, đầu ra, kiểm tra. Thử với request liên quan và không liên quan.

## Lỗi thường gặp

Description quá rộng khiến skill bị gọi sai; lặp toàn bộ handbook; script không được kiểm tra hoặc có side effect ẩn.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Skill đóng gói gì và nên kích hoạt khi nào?

**Vì sao cần ưu tiên:** Điều kiện kích hoạt rõ giúp workflow dùng lại không chạy nhầm nhiệm vụ.

**Gợi ý trả lời:** SKILL.md định nghĩa tên, mô tả và workflow, có thể kèm script và tài nguyên. Mô tả cần nêu cả tình huống phù hợp lẫn giới hạn sử dụng.

Nguồn kiểm chứng: [Build skills](https://learn.chatgpt.com/docs/build-skills).

### 2. Vì sao skill dùng progressive disclosure?

**Gợi ý trả lời:** Nạp metadata ngắn để nhận diện trước, sau đó đọc workflow được chọn và tài liệu cần thiết. Cách này giảm context không liên quan mà vẫn có hướng dẫn chi tiết khi cần.

Nguồn kiểm chứng: [Build skills](https://learn.chatgpt.com/docs/build-skills).

### 3. Skill có shell script. Bạn kiểm tra gì trước khi dùng?

**Gợi ý trả lời:** Đọc script, đầu vào, thao tác ghi file, truy cập mạng và xử lý bí mật. Hướng dẫn dùng lại không thay thế sandbox hoặc quyền thực hiện nhiệm vụ cụ thể.

Nguồn kiểm chứng: [Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security).
