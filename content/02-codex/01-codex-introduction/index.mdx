## Learning objectives

Distinguish a coding agent from autocomplete and write requests with a clear scope and acceptance criteria.

## Prerequisites

Complete the prerequisite lesson: [prompt-engineering-basics](/learn/prompt-engineering-basics). If you already know this material, use the practice questions to assess your understanding.

## Theory

Codex receives a goal, explores a repository, proposes or edits code, and reports the result. Quality depends on repository context, tool permissions, and review criteria. Assign observable outcomes, such as “add validation and tests for this input,” rather than vague requests.

## Architecture

Request → agent reads guidance and relevant code → bounded changes → diff and tests → developer review and merge decision.

## TypeScript example

```ts
type Task = { goal: string; checks: string[] };
const task: Task = { goal: "Validate request payloads", checks: ["reject invalid data", "add focused tests", "summarize changed files"] };
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Choose a small project bug. Write a task describing its goal, scope, constraints, and verification steps. Review the diff as a pull request.

## Common mistakes

Assigning tasks that are too broad; accepting a patch because the explanation sounds confident; forgetting appropriate verification.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How is a coding agent different from autocomplete?

**Why essential:** Observable acceptance criteria make an agent task reviewable.

**Answer outline:** It can inspect a repository, edit files, run commands, and iterate toward a goal. The task therefore needs scope, constraints, and verifiable completion criteria.

Reference: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli).

### 2. What context would you provide for a bug-fix task?

**Answer outline:** Include the reproduction, expected behavior, relevant entry points, repository guidance, and checks. Ask for evidence linking the changed behavior to the original failure.

Reference: [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

### 3. Tests pass. Is the patch ready to merge?

**Answer outline:** Review the diff, requirements, test relevance, and untested paths. A passing command is evidence about the checks it ran, not proof that every requirement is satisfied.

Reference: [Iterating development workflows with Codex](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
