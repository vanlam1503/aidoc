## Mục tiêu học tập

Phân biệt coding agent với autocomplete; viết yêu cầu có scope và tiêu chí nghiệm thu.

## Điều kiện tiên quyết

Hoàn thành bài liên quan trước đó: [prompt-engineering-basics](/learn/prompt-engineering-basics). Nếu đã biết phần này, hãy dùng câu hỏi thực hành để tự đánh giá.

## Lý thuyết

Codex nhận mục tiêu, khám phá repository, đề xuất hoặc sửa code và phản hồi kết quả. Chất lượng phụ thuộc vào context repository, quyền công cụ, và tiêu chí review. Hãy giao việc theo kết quả quan sát được, ví dụ “thêm validation và test cho input này”, thay vì yêu cầu chung chung.

## Kiến trúc

Yêu cầu → agent đọc hướng dẫn và code liên quan → thay đổi có giới hạn → diff/test → người phát triển review và quyết định merge.

## Ví dụ TypeScript

```ts
type Task = { goal: string; checks: string[] };
const task: Task = { goal: "Validate request payloads", checks: ["reject invalid data", "add focused tests", "summarize changed files"] };
```

Đây là đoạn minh họa ranh giới/kiểu dữ liệu; trước production cần bổ sung validation, error handling và quyền phù hợp với use case.

## Thực hành

Chọn một bug nhỏ trong project, viết task theo mục tiêu, scope, điều kiện không được thay đổi và cách kiểm chứng. Review diff như một pull request.

## Lỗi thường gặp

Giao nhiệm vụ quá rộng; xem patch là đúng chỉ vì agent giải thích tự tin; quên yêu cầu chạy kiểm tra phù hợp.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Coding agent khác autocomplete thế nào?

**Vì sao cần ưu tiên:** Tiêu chí nghiệm thu quan sát được giúp đánh giá kết quả của agent.

**Gợi ý trả lời:** Nó có thể đọc repository, sửa file, chạy lệnh và lặp để đạt mục tiêu. Vì vậy nhiệm vụ cần phạm vi, ràng buộc và tiêu chí hoàn thành kiểm chứng được.

Nguồn kiểm chứng: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli).

### 2. Bạn cung cấp context gì cho nhiệm vụ sửa bug?

**Gợi ý trả lời:** Gồm cách tái hiện, hành vi mong đợi, điểm vào liên quan, hướng dẫn repository và lệnh kiểm tra. Yêu cầu bằng chứng nối thay đổi với lỗi ban đầu.

Nguồn kiểm chứng: [Custom instructions with AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

### 3. Test pass thì patch đã sẵn sàng merge chưa?

**Gợi ý trả lời:** Cần đọc diff, yêu cầu, mức phù hợp của test và các luồng chưa kiểm tra. Một lệnh pass chỉ chứng minh các kiểm tra đã chạy, không chứng minh mọi yêu cầu đều đạt.

Nguồn kiểm chứng: [Iterating development workflows with Codex](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex).
