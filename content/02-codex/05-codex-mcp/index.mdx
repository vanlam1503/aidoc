## Theory

**Model Context Protocol (MCP)** is an open protocol for applications to connect to external systems through servers. A host coordinates the application and creates client connections; a client maintains a protocol connection to a server; a server exposes tools, resources, or prompts. MCP standardizes communication, but does not establish business authorization or make a server trustworthy. Check server identity, data scope, arguments, and write actions. [MCP: Architecture](https://modelcontextprotocol.io/docs/learn/architecture)

## Architecture

Host client initializes a connection → discovery returns capabilities → user or agent selects a tool → server handles the request → host displays attributed results.

## TypeScript example

```ts
type ToolCall = { name: "search_docs" | "create_issue"; input: Record<string, string> };
function needsApproval(call: ToolCall): boolean { return call.name === "create_issue"; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Draw flows for a documentation reader and an issue-creation server. Mark data leaving the host and actions requiring human approval.

## Common mistakes

Trusting every MCP server by default; enabling write tools when read access suffices; assuming the protocol enforces business authorization.
