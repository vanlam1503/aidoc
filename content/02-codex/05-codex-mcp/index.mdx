## Theory

**Model Context Protocol (MCP)** is an open protocol for applications to connect to external systems through servers. A host coordinates the application and creates client connections; a client maintains a protocol connection to a server; a server exposes tools, resources, or prompts. MCP standardizes communication, but does not establish business authorization or make a server trustworthy. Check server identity, data scope, arguments, and write actions. [MCP: Architecture](https://modelcontextprotocol.io/docs/learn/architecture)

## Architecture

Host client initializes a connection → discovery returns capabilities → user or agent selects a tool → server handles the request → host displays attributed results.

## TypeScript example

```ts
type ToolCall = { name: "search_docs" | "create_issue"; input: Record<string, string> };
function needsApproval(call: ToolCall): boolean { return call.name === "create_issue"; }
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Draw flows for a documentation reader and an issue-creation server. Mark data leaving the host and actions requiring human approval.

## Common mistakes

Trusting every MCP server by default; enabling write tools when read access suffices; assuming the protocol enforces business authorization.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — How do the host, client, and server relate in MCP?

**Why essential:** Protocol roles and authorization boundaries come before tool integration.

**Answer outline:** The host application manages model interaction and permissions; its clients communicate with servers exposing capabilities. MCP standardizes that integration, rather than supplying the model itself.

Reference: [MCP architecture overview](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture).

### 2. How do tools, resources, and prompts differ?

**Answer outline:** Tools expose callable operations, resources expose readable context, and prompts expose reusable message templates. Describe the data and side effects of each capability explicitly.

Reference: [MCP architecture overview](https://modelcontextprotocol.io/docs/2026-07-28/learn/architecture).

### 3. What security checks belong on a remote MCP server?

**Answer outline:** Validate identity, token audience, scopes, and resource ownership. Restrict downstream access and network destinations; do not assume the host already authorized every requested operation.

Reference: [MCP security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices).
