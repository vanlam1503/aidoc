## Learning objectives

Describe the CLI workflow, choose appropriate permissions, and inspect commands and diffs before proceeding.

## Prerequisites

Complete the prerequisite lesson: [codex-introduction](/learn/codex-introduction). If you already know this material, use the practice questions to assess your understanding.

## Theory

A CLI suits tasks tied to a repository and its existing verification commands. The agent needs the working directory, guidance files, and Git state. Balance read, file-write, and command permissions against their impact; review commands that transfer or delete data carefully.

## Architecture

Terminal session → inspect repository state → agent planning and edits → verification commands → diff review → user decides whether to commit.

## TypeScript example

```ts
type CommandPlan = { command: string; purpose: string; sideEffect: "read" | "write" | "external" };
const plan: CommandPlan = { command: "npm run typecheck", purpose: "check types", sideEffect: "read" };
```

This snippet illustrates boundaries and data types. Before production use, add validation, error handling, and permissions appropriate to the use case.

## Practice

Make a small change on a disposable branch. Record Git state before and after, executed commands, and how to reverse the patch.

## Common mistakes

Allowing all commands without considering side effects; overwriting existing user changes; exposing secrets in terminal logs.

## Interview questions

Original practice questions based on the primary references below, checked on 2026-11-07. These are preparation exercises, not verified questions from a particular employer. Design answers suggest one defensible approach. The literal \* Essential marker indicates editorial priority; start there before the follow-up questions.

### 1. \* Essential — What is the difference between sandboxing and approval policy?

**Why essential:** Execution boundaries matter before an agent runs repository commands.

**Answer outline:** The sandbox limits filesystem and network capabilities. Approval policy controls review of actions needing permission. Instructions in a repository do not themselves grant operating-system access.

Reference: [Codex sandboxing](https://learn.chatgpt.com/docs/sandboxing).

### 2. Why create a Git checkpoint before a CLI task?

**Answer outline:** It gives a reviewable baseline for the agent diff and a recovery point. Inspect existing changes first so the task preserves unrelated work.

Reference: [Codex CLI](https://learn.chatgpt.com/docs/codex/cli).

### 3. A build command is blocked by the sandbox. What next?

**Answer outline:** Identify the missing capability and whether the task requires it. Prefer an allowed equivalent; otherwise request a narrowly scoped escalation and report any verification that remains unavailable.

Reference: [Agent approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security).
