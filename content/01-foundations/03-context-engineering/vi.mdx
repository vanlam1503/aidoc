## Mục tiêu học tập

Hiểu context engineering là chọn và sắp xếp thông tin cần thiết quanh lời gọi model; biết cân đối chỉ dẫn, history, retrieved data và output budget.

## Điều kiện tiên quyết

Hiểu token và context window. Bài này dùng khái niệm prompt từ bài trước.

## Lý thuyết

Prompt engineering tập trung vào chỉ dẫn; **context engineering** xem toàn bộ trạng thái mà model nhìn thấy: system/developer instructions, câu hỏi hiện tại, lịch sử, kết quả công cụ, hồ sơ liên quan, và tài liệu truy xuất. Công việc là đưa đúng thông tin, đúng thời điểm, với cấu trúc dễ phân biệt.

Một pipeline thường gồm: xác định tác vụ → chọn nguồn → lọc/rank → nén hoặc tóm tắt có kiểm soát → dựng context có giới hạn → ghi lại nguồn để kiểm chứng. Giữ dữ liệu có nguồn gốc và thời điểm cập nhật. Tóm tắt history có thể mất chi tiết, nên giữ trạng thái có cấu trúc cho dữ kiện quan trọng.

## Kiến trúc

```text
Request → intent/task → history selector ─┐
                 → retrieval ─────────────┼→ budget + ordering → model
                 → tool results ──────────┘                      → citations
```

Tránh để truy xuất trả về đoạn trùng, lỗi thời, hoặc vượt ngân sách. Context nên gắn nhãn nguồn và phân biệt dữ liệu trích dẫn với chỉ dẫn của ứng dụng.

## Ví dụ TypeScript: dựng context theo budget

```ts
type Chunk = { text: string; tokenEstimate: number; source: string };

function fitChunks(chunks: Chunk[], tokenLimit: number): Chunk[] {
  const selected: Chunk[] = [];
  let used = 0;
  for (const chunk of chunks) {
    if (used + chunk.tokenEstimate > tokenLimit) continue;
    selected.push(chunk);
    used += chunk.tokenEstimate;
  }
  return selected;
}
```

Ví dụ đơn giản này giả định danh sách đã được xếp hạng. Hệ thống production cần tokenizer đúng model, chính sách ưu tiên và kiểm tra cắt cụt.

## Thực hành

1. Với câu hỏi “chính sách hoàn tiền của đơn hàng này?”, xác định dữ liệu cần truy xuất và dữ liệu không cần gửi.
2. Thiết kế budget 6.000 token gồm instructions, history, tài liệu và output.
3. Xác định cách xử lý hai tài liệu mâu thuẫn ngày cập nhật.

## Lỗi thường gặp

- Coi context window lớn là lý do gửi mọi dữ liệu.
- Cắt văn bản giữa một ý hoặc bỏ mất thông tin nguồn.
- Đưa lịch sử cũ không liên quan vào mọi lượt.
- Trộn chỉ dẫn đáng tin với nội dung tài liệu chưa kiểm duyệt.

## Câu hỏi phỏng vấn

Câu hỏi luyện tập tự biên soạn từ các nguồn gốc bên dưới, kiểm chứng ngày 2026-11-07. Đây là bài tập ôn phỏng vấn, không phải câu hỏi được xác nhận từ một nhà tuyển dụng cụ thể. Đáp án thiết kế gợi ý một cách tiếp cận có cơ sở. Dấu \* Essential thể hiện mức ưu tiên biên tập; ôn câu này trước các câu tiếp theo.

### 1. \* Essential — Context engineering khác việc sửa câu chữ prompt thế nào?

**Vì sao cần ưu tiên:** Lựa chọn context quyết định model có thể dùng bằng chứng nào.

**Gợi ý trả lời:** Nó chọn và tổ chức hướng dẫn, bằng chứng truy xuất, lịch sử và kết quả tool trong giới hạn token. Câu chữ tốt không bù được bằng chứng quan trọng bị thiếu.

Nguồn kiểm chứng: [OpenAI prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering).

### 2. Rút gọn hội thoại dài mà vẫn giữ thông tin cần thiết thế nào?

**Gợi ý trả lời:** Giữ mục tiêu hiện tại, quyết định, định danh và việc chưa xong; tóm tắt hoặc bỏ lượt cũ không liên quan. Kiểm tra các dữ kiện và quan hệ tool call còn nguyên.

Nguồn kiểm chứng: [LangChain short-term memory](https://docs.langchain.com/oss/javascript/langchain/short-term-memory).

### 3. Tài liệu liên quan tồn tại nhưng câu trả lời bỏ sót. Debug ở đâu?

**Gợi ý trả lời:** Kiểm tra riêng candidate truy xuất, xếp hạng, bộ lọc, ranh giới chunk và context cuối cùng. Model không thể trích bằng chứng chưa được đưa vào đầu vào.

Nguồn kiểm chứng: [LangChain retrieval](https://docs.langchain.com/oss/javascript/deepagents/retrieval).
