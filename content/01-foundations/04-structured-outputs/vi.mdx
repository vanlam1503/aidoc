## Mục tiêu học tập

Phân biệt JSON mode với schema-constrained output, thiết kế schema có giới hạn, và validate dữ liệu trước khi ứng dụng sử dụng.

## Điều kiện tiên quyết

Biết TypeScript cơ bản và đã học cách mô tả output mong muốn trong prompt.

## Lý thuyết

Nhiều ứng dụng cần output máy đọc được: nhãn phân loại, thuộc tính sản phẩm, hoặc kế hoạch thao tác. Chỉ yêu cầu “trả JSON” trong prompt không bảo đảm JSON hợp lệ hoặc đúng cấu trúc.

**Structured Outputs** là cơ chế hướng model tạo output tuân theo một JSON Schema được hỗ trợ. Điều này giúp ràng buộc cấu trúc và kiểu dữ liệu; nó không xác minh sự thật, tính nhất quán nghiệp vụ hay quyền truy cập. Ứng dụng vẫn phải kiểm tra các điều kiện đó trước khi dùng output để tạo tác động. [OpenAI: Structured Outputs](https://platform.openai.com/docs/guides/structured-outputs)

## Kiến trúc

```text
Input → model với output schema → parse/validate → business rules → side effect
                                         └→ lỗi có kiểm soát / retry policy
```

Tách lỗi định dạng, refusal, lỗi nghiệp vụ và lỗi transport. Không tự động thực thi một hành động nhạy cảm chỉ vì JSON parse thành công.

## Ví dụ TypeScript với Zod

```ts
import { z } from "zod";

const Triage = z.object({
  category: z.enum(["billing", "technical", "other"]),
  urgency: z.enum(["low", "normal", "high"]),
  rationale: z.string().max(500),
});

const result = Triage.safeParse(JSON.parse(modelText));
if (!result.success) throw new Error("Model output did not match triage schema");
```

Trong Responses API, truyền JSON Schema theo cơ chế Structured Outputs chính thức; ví dụ trên minh họa lớp validation ứng dụng sau phản hồi.

## Thực hành

1. Thiết kế schema cho yêu cầu xin nghỉ phép gồm ngày, số ngày và lý do.
2. Thêm giới hạn ngày hợp lệ ở lớp nghiệp vụ.
3. Viết test cho trường thiếu, enum sai, và câu trả lời hợp lệ nhưng không đủ quyền để thực thi.

## Lỗi thường gặp

- Nhầm JSON hợp lệ với dữ liệu đúng.
- Định nghĩa schema quá tự do bằng nhiều trường tùy chọn.
- Tự động retry vô hạn khi schema mismatch.
- Dùng kết quả model trực tiếp cho SQL, shell hoặc quyền truy cập.

### 1. \* Essential — JSON mode khác Structured Outputs thế nào?

**Vì sao cần ưu tiên:** Cần hợp đồng dữ liệu rõ ràng trước khi mã phía sau dùng đầu ra model.

**Gợi ý trả lời:** JSON mode hướng tới JSON đúng cú pháp; Structured Outputs ràng buộc đầu ra theo schema được hỗ trợ. Cả hai không chứng minh dữ kiện nghiệp vụ trong các trường là đúng.

Nguồn kiểm chứng: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### 2. Khi nào dùng function calling thay cho câu trả lời có cấu trúc?

**Gợi ý trả lời:** Dùng function calling để yêu cầu chức năng của ứng dụng; dùng câu trả lời có cấu trúc để trả dữ liệu có kiểu. Mã ứng dụng vẫn quyết định hành động có được phép hay không.

Nguồn kiểm chứng: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling).

### 3. Nếu model từ chối hoặc dừng trước khi hoàn tất thì sao?

**Gợi ý trả lời:** Phân biệt từ chối, sinh chưa đủ và thành công hợp lệ. Không thực thi tác động từ dữ liệu dở dang; hiển thị trạng thái có thể xử lý tiếp và kiểm tra ràng buộc nghiệp vụ.

Nguồn kiểm chứng: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
