# Implementation Plan

## Milestones and definition of done

### Phase 1 — Local learning core

1. Initialize the Next.js App Router, strict TypeScript, Tailwind, and base UI conventions.
2. Add the persistent documentation/curriculum skeleton and local MDX lesson loader with validated frontmatter.
3. Seed substantive foundational lessons and curriculum groups.
4. Build responsive navigation, lesson view, breadcrumbs, TOC, previous/next links, theme control, and reading progress.
5. Generate and use a local full-text search index with difficulty filters.

**Done when:** app starts locally; lessons load from local files; navigation and search work without external services; typecheck and relevant tests pass; diff and known gaps are reviewed.

### Phase 2 — Complete curriculum and references

Populate all Basic, Intermediate, and Advanced topics with distinct lessons following the required lesson structure, including interview preparation. Add the categorized reference library, related-lesson links, verified-date fields, and GitHub stars only where the API provides them. Add content validation and index scripts.

### Phase 3 — Local learning persistence

Persist progress, bookmarks, conversations, messages, and usage in a versioned local JSON store. Provide an immediately usable dashboard and lesson actions without login or database setup. Validate writes and reject cross-origin requests.

### Phase 4 — AI assistant

Add the official Google Gen AI SDK and streaming Gemini API, local chunk retrieval, citations to lesson paths/IDs, streaming, bounded local conversation history, Zod validation, timeouts, error handling, and workspace quotas. Render an explicit configuration state when the API key is absent.

### Phase 5 — Quality and operations

Add Vitest unit/integration coverage and Playwright end-to-end journeys, accessibility review, security review, performance work, CI guidance, and complete setup/architecture/known-limitations documentation.

## Local store outline

`src/lib/local/store.ts` owns `.data/academy.json`, schema validation, UUIDs, progress/bookmark updates, bounded conversations, and usage reservations. Mutations are serialized per file and committed through atomic rename. OAuth and database implementation/dependencies were removed for personal local use.

## Testing strategy

- Unit: frontmatter validation, lesson discovery/order, search tokenization/ranking, content link integrity, and retrieval ranking.
- Integration: route validation/origin guards, local persistence and concurrency, chat quota/error paths, and citation formatting.
- E2E: browse lessons anonymously, search/filter/open a lesson, navigate mobile sidebar, theme toggle, local progress/bookmarks and dashboard, and chat when configured.
- Operational checks: strict TypeScript, production build, content validator, local persistence checks, and manual accessibility/keyboard pass.
